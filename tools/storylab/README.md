# Story Lab — 키즈 안내 콘텐츠 로컬 생성기

여행 경로를 넣으면 키즈 안내에 필요한 것을 실제로 생성하고, 차량 화면과 같은 방식으로 조합해 브라우저에서 검토한다. 앱과 분리된 검증 도구다.

## 실행

```bash
python tools/storylab/server.py
```

`http://127.0.0.1:8790`을 연다. 이 PC에서만 접속된다.

- 글: `gemini-4-argon`, 그림: `gemini-nano-banana-2.1`. 둘 다 이 PC에서 도는 OpenAI 호환 생성 서버를 거친다. 주소와 키는 환경 변수 `STORYLAB_LLM_URL`, `STORYLAB_LLM_KEY`로 주며, 기록하거나 출력하지 않는다.
- 장소 소개문: 한국관광공사 TourAPI. 키는 `local.properties`의 `TOUR_API_KEY`(차량 앱과 같은 출처).
- 필요한 것: Python 3.10, Pillow, numpy.

## 생성 순서

1. **소개문** — 장소 이름으로 관광공사 자료를 찾는다. 관광지·문화시설 가운데 제목이 그 이름이거나 그 이름으로 끝나는 것만 받는다. 이름만 걸친 가게나 숙소가 잡히면 틀린 이야기가 만들어지므로, 못 찾으면 그 장소는 건너뛰고 메모에 남긴다.
2. **여행 이야기 틀** — 경로 전체를 꿰는 틀(모으기·수수께끼·돕기·편지 전하기 중 하나), 목표, 끝맺음, 장소마다의 친구(NPC)와 건네는 것을 정한다.
3. **장소 원고** — 그림책 8쪽, 가는 길 퀴즈 3개, 창밖 힌트, 회상, 도착 미션, 배경 2장의 설명, 소품 3~5개. 쪽마다 배경·친구 동작·소품을 배정한다.
4. **그림** — 배경 2장, 친구 4동작 시트 1장, 소품 시트 1장. 시트는 단색 배경으로 받아 `scripts/cut_stickers.py`로 한 개씩 자른다.

사용자가 넣는 것은 장소 목록뿐이다. 목적과 나이대는 고를 수 있지만 고르지 않으면 기본값으로 진행한다. 순서, 직전 장소, 마지막 장소 여부 같은 상황 값은 코드가 채운다.

## 규격과 검증 (`spec.py`)

- 지침은 차량 앱의 `StoryKit.java`와 같은 규칙(사실 규칙, 말투, 쪽 구성, 문장 꼴)에 여행 틀·친구·소품·배경을 더한 것이다.
- 모델이 돌려준 값은 그대로 쓰지 않는다. 길이·허용 값·id 참조를 확인해 어긋난 항목은 버리고 화면의 "검증 메모"에 남긴다. 쓸 수 있는 쪽이 5쪽 미만이면 한 번 다시 쓰게 하고, 또 실패하면 그 장소를 건너뛴다.
- 퀴즈를 읽는 꼴과 정답 안내는 코드가 조립한다. 일반 안내용 사실은 모델이 쓰지 않고 소개문에서 잘라 쓴다.
- 그림 지시문의 화풍 부분은 코드에 고정돼 있고, 모델은 "무엇을 그릴지"만 영어로 적는다.

## 결과물

`out/<실행 id>/run.json`에 진행 기록, 여행 틀, 장소별 원고(차량 앱의 장소 형식과 같은 필드), 검증 메모가 들어가고, `out/<실행 id>/p1/` 아래에 `cut-*.jpg`, `npc/*.png`, `props/*.png`가 저장된다.

## 아직 아닌 것

- 차량 앱의 실제 생성 경로(`ContentService`)에는 연결하지 않았다. 앱은 Gemini API를 직접 부르고 이 도구는 로컬 서버를 거친다.
- 원고의 사실 여부를 소개문과 자동으로 대조하지 않는다. 지침으로 막고 사람이 검토하는 단계다.
- 스티커 자르기는 개수가 맞지 않으면 그 시트를 통째로 버린다.
