# Cabin Story — 협동 여행 경로 플래너로 재정의

2026-11-14 사용자 정정. 이 문서는 이전 implementation-plan의 '경주 4곳 한 여행', '장기 기록 제외'와 이미지 기반 uiux-design-review의 제품 우선순위를 대체한다. 기존 WebGPT 이미지 9장은 사용자 평가에 따라 사용 중지한다. 파일은 삭제하지 않으며 디자인 기준/제품 자산으로 사용하지 않는다.

## 서비스의 중심

협동 여행 경로 플래너 + 음성 도슨트 + 여행 경로 기록. 계획 → 가족 협의/편집 → 차량 이동과 장소 도슨트 → 방문 결과 기록이 한 여행으로 이어진다. 장소 목록과 도슨트만으로 구현 완료라고 하지 않는다.

사용자가 확정한 기록 범위는 **계획 경로와 방문 완료 장소·시간**이다. 지속적인 GPS 이동 궤적 수집은 하지 않는다. 사용자는 API 키 없이 가능한 공개 지도·경로로 우선 구현하는 방식을 선택했다. 오프라인만/장소4곳/3분은 공모전 강제 조건이 아니며 이 서비스 범위를 임의로 제한할 근거로 사용하지 않는다.

## 핵심 화면과 행동

- 경로 플래너가 첫 화면. 모바일은 상단 지도(약 40vh, 최소280px) → 도로 경로 거리/예상시간 → 출발지/방문 순서 → 장소 검색/추가. 넓은 화면과 정차 차량은 지도와 편집 패널 2열. Material spacing/type/state를 유지하되 삽화 대시보드를 중심에 두지 않는다.
- 새 표현 기준은 흰색/연회색 surface(#F8FAFC), 짙은 남색 본문(#16324F), 파랑 primary/계획경로(#245AE8), 초록 방문완료(#1B7F59), 주황 변경제안(#C76A19). Material 8px 간격, 48px 모바일/64dp 차량 조작, 16px 본문, 24~28px 제목. 지도·경로·목록이 우선이며 캐릭터·장식 삽화는 플래너 첫 화면에 넣지 않는다. 하단 목적지는 경로/도슨트/기록/가족. 주행 음성은 예외 화면이다.
- 새 여행 제목, 출발지, 여러 방문지/최종 목적지를 직접 지정한다. 지도에서 지점을 고르거나 장소명을 명시적으로 검색한다. 검색한 장소는 기존 도슨트 장소와 분리되며 원고가 없는 장소에 이야기를 만들어 표시하지 않는다.
- 방문 순서를 바꾸면 기존 경로를 '변경 전' 상태로 표시하거나 숨기고, 새 도로 경로 미리보기를 요청한다. 오래된 응답을 새 일정에 붙이지 않는다. 계산 실패 시 직선을 실제 도로 경로로 대체하지 않는다. 예상 거리/시간은 서비스 제공 예측치로 표시한다.
- 가족은 같은 계획/지도와 변경을 본다. 조회/제안/편집 권한을 재사용한다. 제안은 운전자가 수락/거절하며, 일정 확인과 실제 내비 요청은 별도다.
- 여행 시작 시 계획 경로/순서를 보존한다. 방문 완료는 장소와 최초 완료 시각을 저장한다. 재확인으로 시간을 덮어쓰지 않는다. 여행 완료 시 계획·최종 일정·방문 결과를 보존한다. 다음 여행 편집으로 과거 기록을 덮어쓰지 않는다.
- 기록 화면에서 여행 목록, 계획 경로 지도, 완료/미방문 목록과 시각을 본다. '여행 시작/종료' 시각과 '장소 방문 완료' 시각을 구별한다. 기존 방문 데이터의 시각은 알 수 없음으로 유지한다.
- 도슨트는 선택 장소/다음 방문지에 연결된 보조 화면. 원고가 있는 경주 4곳은 기존 성인/어린이 내용을 재사용하고 나머지는 '등록된 해설 없음'을 표시한다.
- 차량 주행/상태 미확인은 지도 편집/권한/기록 조작을 제한하고 음성 UI 유지. 정차 시 실제 플래너와 기록 사용. 안전 제한을 앱 내부 모의 상태와 구분한다.

## 데이터/책임

TripStore는 여행 상태·자유 장소·출발지·권한·버전·기록의 단일 저장 책임. active trip과 다른 여행 archive를 한 SharedPreferences 편집에서 원자적으로 저장. 기존 trip을 손실 없이 마이그레이션하며 기존 시간은 발명하지 않는다. tripId는 샘플 상수가 아닌 새 UUID. 제목과 장소명은 trim/길이/제어문자/유한 좌표를 검증한다. 계획 경로 geometry는 routeRevision과 연결하고 장소 순서/출발지 변경 시 무효화한다.

MapService는 공개 장소 검색/도로 경로 요청, 제한된 대기시간/응답 크기, 앱 식별 User-Agent, 요청 속도 제한/캐시, 응답 좌표 검증을 담당한다. 사용자가 명시적으로 요청한 공개 장소/좌표만 전송한다. 기기 이름·토큰·방문 시각·기록은 외부 지도에 보내지 않는다. 지도 타일은 화면에서 보는 범위만 브라우저 기본 캐시로 요청하며 대량 다운로드 기능을 제공하지 않는다.

FamilyServer는 기존 인증·origin·본문 길이 제한을 유지하고 검색/경로 API와 planner 정적 자산을 제공한다. 외부 임의 URL 프록시를 만들지 않는다. Native 차량 플래너의 운전자 권한은 모바일 초대 코드로 획득할 수 없어야 하며, 로컬 WebView bridge 접근은 앱 소유 페이지로 한정한다.

Pleos NaviHelper 3.0.5는 requestRouteWithWaypoints와 requestNavigationScreen API가 존재함을 설치 jar와 공식 문서에서 확인했다. WaypointIndex는 FIRST/SECOND로 경유지2개. 플래너의 장소 개수를 이에 맞춰3개로 제한하지 않는다. SDK가 한번에 처리할 수 없는 일정은 요청 범위를 명시하고 추가 구간을 조용히 누락하지 않는다. 공개 도로 미리보기 경로와 실제 차량 내비 경로는 공급원이 달라 차이가 있을 수 있다.

## 공개 서비스 선택과 실제 확인 출처

- 지도 표시: Leaflet 1.9.4 stable를 앱에 포함. https://leafletjs.com/install.html
- 타일: OpenStreetMap standard. 화면 attribution/유효 Referer/브라우저 캐시, bulk/offline 다운로드 금지. https://operations.osmfoundation.org/policies/tiles/
- 검색: Photon public demo. 적당한 요청량, 명시 검색/서버 캐시/속도제한. 가용성 보장 없음. https://github.com/komoot/photon
- 도로 경로: FOSSGIS OSRM public service. 최대1req/s, 실제 단위/실패 표시와 출처 제공. https://routing.openstreetmap.de/about.html
- 내비 다중 경유지: https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/NaviHelper/route-with-waypoints
- SDK 버전/좌표 인자 순서/사용자정의경로 결과 제거: https://document.pleos.ai/docs/pleos-only/release-note/sdk-release-note

공개 서버 기반은 우선 검증용이며 대규모 상용 운영의 무제한 무료 인프라로 설명하지 않는다. Nominatim public endpoint는 이번 구현에서 사용하지 않는다. 공개 공급자 실패/검색 품질/한국 도로 데이터 한계를 직접 검증하고 기록한다.

## 순차 구현/인수

R1 여행 도메인/기록 → R2 지도 검색·도로 경로 서비스와 서버 계약 → R3 모바일 지도 플래너·기록 → R4 정차 차량 플래너·기록/내비 연결 → 통합 QA/산출물. 제품 코드는 DeepSeek, 설계·테스트·인수는 GPT. 한 유닛을 검토한 뒤 다음 유닛으로 이동한다.

인수 기준: 새 여행 생성/보존, 자유 장소·출발지 변경, 도로 geometry 표시와 순서 변경 재계산, 검색 실패/경로없음/오프라인/오래된 응답, 권한별 협업과충돌, 시작 계획 스냅샷 불변, 방문시간 중복방지, 과거기록 보존/복원, 원고없음 처리, 주행잠금, 실제 Pleos 요청과 결과 구분. 빌드와 서명, 실제 에뮬레이터·브라우저 조작으로 확인한다.
