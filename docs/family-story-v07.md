# Family Story 0.7 — 차량 조작 단순화 · 승인 절차 제거 · 안내 분량 확대

2026-11-15. [0.6](family-story-v06.md) 위에서 바꾼 것만 적는다. 0.6의 "제안 → 운전자 수락" 구조는 이 버전에서 없어졌다.

## 1. 승인 절차 제거

- 가족 기기가 담은 장소는 곧바로 차량 목록에 들어간다. 제안 카드, "일정에 추가/넘기기", "운전자 일정 확인"이 모두 없어졌다.
- 연결한 기기는 처음부터 '장소 담기' 권한을 받는다. 차량에서 권한을 줄 필요가 없다. 권한은 보기만 / 장소 담기 / 담기와 정리(순서·빼기) / 연결 해제.
- 여행 시작에 필요하던 출발지, 도로 경로 미리보기, 일정 확인 조건을 없앴다. 차량에서 갈 곳을 처음 고르면 여행이 시작된다(`go` 동작).
- 예전 클라이언트가 보내는 `propose`/`proposeCustom`은 서버에서 `add`/`addCustom`으로 처리한다.
- 주행 중 누가 장소를 담으면 한 번 읽어 준다: "민지가 황리단길을 가고 싶은 곳에 담았어요. 정차하면 목록에서 고를 수 있어요." 정차 중이면 화면 위쪽 알림 띠로 보여 준다.

## 2. 차량 화면

탭은 경로 · 안내 · 설정 세 개다. 지도가 있던 계획 탭은 차량에서 뺐다. 차량의 지도는 차량 내비 하나만 쓴다.

**경로(정차)**
- 위: "지금 가는 곳 · 대릉원 · 3시간 30분 · 310km 남음 · 내비 기준". 목적지가 없으면 "어디로 갈까요?".
- 아래: 장소 목록(2열 큰 칸, 한 화면 6곳). 칸을 누르면 그곳이 목적지가 되고 차량 내비에 안내를 요청한다. 확인 창은 없다.
- 버튼은 하나: "내비에서 가져오기"(내비의 현재·최근 목적지를 누르면 바로 담김. 없으면 내비 검색을 연다). 모두 다녀오면 "여행 마치기", 마친 뒤에는 "새 여행"으로 바뀐다.
- 없앤 것: 출발 준비 체크리스트, 일정 확인, 여행 시작, 방문 완료, 안내 듣기, 방문 순서 패널, 내비 요청 확인 창.
- 중간에 여행을 마치려면 설정 › 기록의 "지금 여행 마치기".

**안내(정차)**
- 한 장짜리 구성: 그림과 장면 글이 화면을 차지하고, 장소 이름 · 일반/키즈 · 이전/듣기/다음은 아래 한 줄에 둔다. 아주 넓은 화면에서만 그림과 글을 나란히 놓는다.

## 3. 휴대폰 계획 화면

- 순서: 장소 찾기 → 가고 싶은 곳 → 지도. 검색 결과의 버튼은 "담기" 하나다.
- 숨긴 것: 출발지, 도로 경로 미리보기와 구간별 거리, 일정 확인, 여행 시작/완료, 가족 제안, 좌표 직접 입력, 저장된 여행, 변경 내역.
- 지도는 담은 곳의 위치를 보여 주는 용도로 작게 남겼다.

## 4. 안내 분량

| | 0.6 | 0.7 |
|---|---|---|
| 키즈 동화(장소당) | 3쪽 | 8쪽 |
| 일반 해설(장소당) | 3문단 | 7~8문단 |
| 장소별 퀴즈 / 사실 | 1 / 1 | 3 / 3 |
| 어느 구간에서나 쓰는 이동 프로그램 | 없음 | 퀴즈 12, 창밖 놀이 12, 몸 풀기 6, 연속 이야기 8편 |

- 이동 중(키즈): 출발 이야기 뒤로 퀴즈 → 창밖 놀이 → 별 조각 이야기 → 퀴즈 → 몸 풀기 → 창밖 놀이 → 별 조각 이야기 순서로, 앞 이야기가 끝나고 40초 뒤에 다음 것을 말한다. 남은 시간이 2분 30초 아래로 내려가면 멈추고 "곧 도착"으로 넘어간다.
- "별 조각 이야기"는 길잡이가 별 조각 일곱 개를 찾는 8편짜리 이야기로, 구간이 바뀌어도 이어서 들려준다.
- 장소 퀴즈를 먼저 쓰고, 다 쓰면 공통 퀴즈로 넘어간다. 내장 장소가 아닌 곳으로 갈 때도 공통 프로그램은 그대로 나온다.
- 이동 중(일반): 장소 사실을 2분 간격으로 최대 3개.
- 문구는 `places.json`의 각 장소 `journey`와 맨 아래 `program`, 순서는 `CabinSessionService.playNextSegment`.
- 설정 › 음성·안내의 "이동 중·도착 때 자동으로 안내"를 끄면 모두 나오지 않는다.

## 5. 새 장소의 안내 생성 규격 (StoryKit)

내장 4곳과 새로 담은 장소가 같은 모양의 안내를 갖도록, 규격·작성 지침·검증을 `StoryKit.java` 한 곳에 모았다.

- **규격**: 그림책 8쪽, 가는 길 퀴즈 3개, 창밖 힌트, 회상 한 줄, 도착 미션, 일반 안내용 사실 3개. 내장 장소의 `kids`·`journey`·`mission`과 같은 필드다.
- **지침**(`StoryKit.prompt`): 독자(5~7세), 길잡이 이름 자리표시자, 사실 규칙(소개에 없는 내용 금지, 바뀌는 정보 금지), 말투, 쪽별 구성(인사 → 내용 5쪽 → 약속 → 마무리 활동), 퀴즈·힌트·미션의 문장 꼴.
- **응답 형식**(`StoryKit.schema`): Gemini에 필드 구조를 지정해 요청한다. 모델이 형식을 거부하면 일반 JSON으로 한 번 더 요청한다.
- **검증**(`StoryKit.parse`): 길이·동작 값·퀴즈 정답 번호를 확인하고 어긋난 항목은 버린다. 쓸 수 있는 쪽이 5쪽 미만이면 통째로 버리고 짧은 기본 원고를 쓴다.
- **고정 문장은 코드가 만든다**: 퀴즈를 읽는 꼴("… 일 번, ○. 이 번, ○.")과 정답 안내("정답은 일 번! …")는 모델이 아니라 코드가 조립한다.
- **일반 안내의 사실**은 모델이 쓰지 않고 한국관광공사 소개문의 문장을 잘라 쓴다.
- 예전 규격(3쪽)으로 만든 장소는 다음 준비 때 새 규격으로 다시 만든다. 실패하면 기존 원고를 그대로 둔다.
- 실제 Gemini 호출은 확인하지 못했다(크레딧 소진). 지침대로 된 응답과 어긋난 응답을 넣어 검증·저장·퀴즈·미션 연결까지를 테스트로 확인했다.

## 확인

- 계측 테스트 42개 통과(아래 37개에 StoryKit 5개 추가)(`evidence/family-tests.txt`). 승인 없이 담기, 목적지 선택으로 여행 시작, 이동 프로그램 분량을 추가했다.
- 차량 에뮬레이터: 경로 화면에서 대릉원을 한 번 눌러 실제 내비가 경로를 잡고, 화면에 "지금 가는 곳 · 3시간 30분 · 310km · 내비 기준"이 뜨는 것. 안내 화면의 새 배치(일반, 키즈 1/8).
- 모의 이동 로그: 출발 이야기 → 퀴즈 → 창밖 놀이 → 별 조각 이야기 → 퀴즈 → 곧 도착 → 본편 1/8, 2/8.
- 휴대폰 웹 화면(375px): 연결 직후 권한 변경 없이 검색 결과를 "담기"로 목록에 넣음.

## 미확인

- 네이티브 휴대폰 앱의 바뀐 문구와 "차량으로 보내기"(빌드만 확인, 화면은 웹 계획 화면으로 확인).
- 주행 중 "담았어요" 음성, 정차 중 알림 띠, "내비에서 가져오기", "새 여행", "지금 여행 마치기" 버튼.
- 실제 주행 속도에서의 이동 프로그램 간격(모의 이동은 간격을 6초로 줄여 확인).
- 차량에서는 장소를 뺄 수 없다. '담기와 정리' 권한의 휴대폰에서 뺀다.
- `NAVI_CUSTOM_MAP` 권한을 매니페스트에 추가했다(내비 검색 화면 호출에 필요하다고 SDK가 표시). 실차에서의 동작은 보지 못했다.
- 실차, 실물 휴대폰.
