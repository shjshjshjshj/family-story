# Family Story 0.3 — 차량 허브 + 휴대폰 개인 앱

2026-11-15. 서비스명을 **Family Story**로 바꾸고 차량용·휴대폰용을 각각의 플랫폼 문법으로 다시 구성했다. 이 문서가 현재 구조의 기준이며, README의 0.1~0.2 설명 중 이 문서와 다른 부분은 이력이다.

## 두 앱의 역할

| | 차량용 (`:app`, `kr.cabinstory`) | 휴대폰용 (`:phone`, `kr.familystory.phone`) |
|---|---|---|
| 성격 | 가족 전용 허브, 도슨트 플레이어 | 개인용 활동 공간, 맞춤형 안내(일반/키즈) |
| 화면 문법 | 좌측 레일 4개, 64dp 이상 조작, 스크롤 없는 한 화면(긴 목록은 쪽 넘김) | Material 3, 하단 내비게이션 4개, 48dp 조작 |
| 주행 중 | 경로·안내만. 큰 글자 + 버튼 1~2개, 그림·본문 숨김 | 제한 없음(동승자) |
| 인터넷 검색 | 없음 | 안내 화면의 네이버/구글/다음 검색 버튼(일반 안내만) |

공통 GNB: **경로**(진행 중인 여행) · **계획**(경로 기획, 지도) · **안내**(도슨트) · **설정**(가족 관리 + 기록, 차량은 음성·연동 포함).

패키지 이름 `kr.cabinstory`는 기존 설치본·서명과의 연속성을 위해 유지하고 표시 이름만 바꿨다.

## 권한과 안내 유형

그룹 오너는 차량(운전자)이다. 정차 중 차량의 설정 › 가족에서 기기별로 정한다.

- 권한: 조회만 / 장소 제안 / 일정 편집 / 연결 해제
- 안내 유형: 일반 안내 / 키즈 안내 — 휴대폰 안내 탭이 이 값에 따라 달라진다. 휴대폰에서 스스로 바꿀 수 없다.

휴대폰은 차량에 보이는 주소와 6자리 초대 코드로 참여한다(같은 Wi-Fi, 참여 시도는 주소당 초당 1회 제한).

## 길잡이 캐릭터

- 여성 목소리 = 고양이 **나비**, 남성 목소리 = 강아지 **보리**. 차량 설정 › 음성·안내에서 고르면 TTS 화자와 캐릭터가 함께 바뀐다.
- Pleos TTS `setSpeakerType`에 넣는 값은 SDK 문서에 없어 에뮬레이터의 음성 서비스에서 확인했다: 한국어 화자 `HAEUN`·`SEOYOON`(여), `EUNWOO`·`SANGHYEOK`(남). 앱은 `HAEUN`/`EUNWOO`를 쓴다. 현재 화자를 읽는 공개 API는 없어 앱 설정이 기준이다.
- 활동 종류 8개와 스프라이트: `wave`(인사) `point`(가리키기) `walk`(걷기) `think`(궁금) `read`(책) `cheer`(신남) `stargaze`(망원경) `photo`(사진). 캐릭터당 8장, `assets/sprites/{dog,cat}/`.
- 키즈 원고의 각 쪽에 `activity`를 미리 지정한다. 원고의 `{g}`는 현재 길잡이 이름으로 바뀐다. 지정이 없으면 본문 키워드로 고른다(`ContentService.activityFor`).
- 스티커는 장소 그림 위에 얹고 활동별로 작은 반복 움직임을 준다(흔들기·걷기·점프 등).
- 원화는 ChatGPT 웹에서 캐릭터당 한 장의 4×2 시트로 만들었고 `scripts/slice_sprites.py`로 잘랐다. 원본은 `design/characters/`.

## 안내 이미지

- 일반: 한국관광공사 TourAPI 사진. 키즈: Gemini 이미지 모델로 만든 동화풍 장소 그림(캐릭터 없음) + 길잡이 스티커.
- 여행을 시작하면 차량이 방문지마다 한 번 준비해 기기에 저장하고, 이후에는 인터넷 없이 보여 준다(`ContentService`). 해설이 없는 장소는 TourAPI 개요로 일반 원고를 만들고 키즈 원고는 Gemini로 만든다(실패 시 기본 3쪽).
- 시연용 경주 4곳은 미리 넣었다(`assets/media/`). 사진은 `scripts/prepare_demo_media.py`(TourAPI), 키즈 동화 그림 4장은 Gemini 크레딧 소진으로 ChatGPT 웹에서 만들었다(원본 `design/kids-backgrounds/`).
- 키는 `local.properties`(git 제외)에서 빌드 때 읽는다. APK에 들어가므로 추출될 수 있다. 한도를 건 시연용 키만 쓴다.

## 장소 검색과 차량 내비 — 내비 우선

NaviHelper에는 검색 결과를 앱으로 돌려주는 API가 없다. 대신 내비가 실제로 잡은 목적지·경유지는 읽을 수 있다.

1. 휴대폰·지도에서 넣은 장소는 "내비 확인 전" 후보다.
2. 차량에서 "내비로 안내"를 요청하면 내비가 돌려준 이름·주소·좌표·POI ID로 그 장소를 덮어쓴다(`TripStore.syncNavi`, 2km 이내 응답만). 좌표가 30m 넘게 달라지면 도로 미리보기를 무효화한다.
3. 차량 계획 화면의 "내비에서 장소 찾기"는 내비 검색 화면을 열고, "내비 장소 가져오기"는 내비의 현재 목적지·최근 목적지를 방문지로 추가한다(처음부터 내비 기준).
