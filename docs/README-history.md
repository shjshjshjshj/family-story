# Family Story · 패밀리 스토리 (구 Cabin Story)

> **0.3 (2026-11-15):** 서비스명을 Family Story로 바꾸고 차량용 허브 앱과 휴대폰용 네이티브 앱으로 재구성했습니다. 현재 구조는 [Family Story 0.3](docs/family-story-v03.md), 이후 고도화는 [0.4](docs/family-story-v04.md)와 [0.5 이동 구간 이야기·차량 팝업 교체](docs/family-story-v05.md), [0.6 계획 넘기기·창밖 모드](docs/family-story-v06.md), [0.7 차량 조작 단순화·승인 절차 제거·안내 분량 확대](docs/family-story-v07.md), [0.8 준비: 그림책 층 구성·로컬 생성기](docs/family-story-v08.md)가 기준이며(제안·승인 구조는 0.7에서 없어짐), 아래 본문 중 그와 다른 설명은 이전 버전의 이력입니다. APK: `apk/FamilyStory_car_release.apk`, `apk/FamilyStory_phone_release.apk`.

> **제품 범위 재정의 / 구현 진행 중 (2026-11-14):** 협동 여행 경로 플래너 + 음성 도슨트 + 계획 경로·방문 장소/시간 기록으로 변경합니다. 생성 컨셉 이미지는 사용하지 않습니다. 아래의 경주 4곳/단일 여행/기록 제외 설명은 초기 0.1 MVP의 이력이며 새 제품 범위의 제한이 아닙니다. 새 설계는 [플래너 재정의](docs/planner-rebaseline.md), 진행·인수 결과는 [플래너 QA](docs/planner-qa.md)를 봐 주세요. 개발 중 APK는 최종 인수본과 구분합니다.

**하나의 여행길, 우리 가족만의 서로 다른 이야기.** Pleos Connect 차량에서는 한국어 음성 도슨트, 동승자 휴대폰에서는 같은 장소의 그림책·설명·공유 일정을 제공하는 오프라인 여행 MVP입니다.

기획서의 F1~F5를 기반으로 구현했습니다. 기획서의 제안과 기술 가정은 검증 상태를 따로 표시합니다. 기존 `../starter` TTS 시험 앱은 수정하지 않았습니다.

## 실행

1. Pleos Connect Emulator **v2.1.0 / Android 14(API 34), x86_64 / 2560×1440 가로**를 Cold Boot합니다. 차량 셸 안에서 앱이 차지하는 영역은 시스템의 창 배치에 따라 더 작습니다.
2. `apk/CabinStory_CabinStory_release.apk`를 설치하고 **캐빈 스토리**를 실행합니다.
3. 실제 P단 신호가 확인되면 일정·가족·진단을 조작할 수 있습니다. 주행 또는 상태 미확인 때는 음성 제어만 허용합니다.
4. `연동 진단 → 위치 접근 허용`으로 Pleos 위치 권한을 허용합니다. 에뮬레이터의 커스텀 권한 팝업은 ‘알 수 없는 작업’으로 표시될 수 있습니다. 앱이 요청하는 권한은 `pleos.car.permission.FUSED_LOCATION`입니다.

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adb install -r .\apk\CabinStory_CabinStory_release.apk
& $adb shell am start -n kr.cabinstory/.MainActivity
```

Debug와 release의 서명 키는 다릅니다. 기존 debug 앱 위에 release를 설치하면 서명 불일치로 실패합니다. 데이터 보존이 필요하면 다른 QA AVD를 사용하세요. 사용자가 쓰던 앱을 자동 삭제하는 설치 스크립트는 제공하지 않습니다.

## 가족 기기 연결

**휴대폰 앱 설치 없이 브라우저로 참여**합니다. 차량 앱이 내장 HTML/CSS/JS·삽화를 제공하고 동일한 여행을 저장·검증합니다. 서버·외부 폰트·계정·클라우드 서비스가 필요하지 않습니다.

- 실제 로컬망: 차량과 휴대폰을 같은 개인 핫스폿/Wi-Fi에 연결하고, `가족 연결` 화면의 초대 주소를 엽니다.
- PC와 에뮬레이터: `adb forward tcp:8787 tcp:8787` 실행 후 PC에서 `http://127.0.0.1:8787/phone`을 열고 차량 초대 주소의 `#` 뒤 코드를 입력합니다.
- 실물 휴대폰과 에뮬레이터: 에뮬레이터의 `10.0.2.x` 주소로 직접 접속할 수 없습니다. 신뢰할 수 있는 시연망에서만 PC의 LAN 포트 포워딩과 방화벽 설정이 필요합니다. 이번 작업에서 실물 휴대폰 연결은 검증하지 않았습니다.

가족은 조회 권한으로 참여하며, 차량의 `권한 관리`에서 **조회 / 제안 / 편집 / 철회**를 지정합니다. 편집자는 추가·삭제·순서 변경을 하고, 제안자는 후보 장소를 제안합니다. 차량에서 제안을 수락하거나 거절할 수 있습니다. 일정은 버전으로 검사하며 동시 변경은 자동 병합하지 않고 최신 일정 확인을 요청합니다.

앱이 화면에서 종료되면 로컬 서버·초대·기기 권한은 종료되고, 여행 일정은 기기에 남습니다. 연결 중단 때 휴대폰에는 마지막 수신 일정과 연결 끊김을 표시하며 편집을 막습니다. 계정이나 실제 아동 개인정보는 저장하지 않습니다. 기기 이름은 임의 별칭을 쓰세요.

**HTTP 연결은 암호화되지 않습니다. 개인 시연망에서 샘플 여행 데이터로만 사용하세요.** 초대 링크를 가진 같은 망 사용자는 조회 기기로 참여할 수 있고, 편집 권한은 운전자가 따로 부여합니다. 상용 배포 전 TLS·기기 인증·보호자 및 개인정보 정책을 보완해야 합니다.

## 구현한 기능

- 첨성대·대릉원·동궁과 월지 기본 일정, 국립경주박물관 추가 후보. 공통 `tripId` / `placeId`, 순서·방문 완료·변경 이력·로컬 저장.
- Pleos **TextToSpeech 3.3.1 / ON_DEVICE / ko-KR**. 재생·일시정지·이어서 듣기·정지. SDK에 정확한 일시정지 API가 없어 멈춘 문단의 처음부터 다시 읽습니다. 다른 오디오가 포커스를 요청하면 멈추며 자동 재개하지 않습니다.
- 여우 **루루**와 장소별 창작 삽화 4장, 장소당 키즈 3장면·일반 설명 3문단, 원천 안내 링크. 자세한 설명과 검색은 동승자 기기에 배치했습니다. 검색은 내장 4곳에 한정합니다.
- 실제 Vehicle P단 조회·리스너. 신호가 오래됐거나 P가 아니면 일정·권한 편집을 제한합니다. 실차 안전 인증을 의미하지 않습니다.
- NaviHelper 3.0.5 연결·정보/도착 이벤트 수신, 정차 중 선택한 **한 곳**의 목적지 요청. **전체 다중 경유지 경로 적용은 구현하지 않았습니다.** 일정 확인과 내비 반영은 다른 단계입니다. 목적지 응답이 맞는지 확인하기 전 성공으로 표시하지 않습니다.
- FusedLocation 1.1.3 실제 위치 콜백, 30초 이내 위치가 선택 장소 250m 안이면 장소당 한 번 접근 처리. 자동 음성은 운전자가 켜야 합니다. 위치는 정차 판정에 사용하지 않습니다.
- 에뮬레이터에만 모의 정차·주행·접근 모드. 하단 `시연 모드`에서 선택하며, 모의 모드에서는 실제 내비 요청을 차단합니다. 모의 주행 화면 캡처는 실제 주행 검증 증거가 아닙니다.

## 빌드 및 테스트

JDK **19**, Gradle Wrapper **8.13**, AGP **8.7.3**, compile/target **35**, minSdk **28**. JDK 17~23과 Android SDK가 필요합니다. 첫 빌드는 Google/Maven Central/Pleos 저장소에서 개발 의존성을 내려받습니다. 앱 실행 시 인터넷은 필요하지 않습니다.

```powershell
.\build.ps1        # 서명된 release + debug + 테스트 APK, lint
.\build.ps1 -Test  # 위 빌드 + 연결된 에뮬레이터에서 12개 테스트
.\package.ps1      # outputs/CabinStory-source-release.zip · 소스와 release APK만 묶기
```

`signing/`에 로컬 release 키와 비밀번호를 생성하며 저장소·소스 패키지에는 포함하지 않습니다. 같은 설치를 업데이트하려면 해당 로컬 키를 보관해야 합니다. 배포용 정식 키가 아닙니다. `CabinStory`는 패키징용 임시 팀 표기이므로 실제 제출 전 파일명을 `팀명_앱이름_release.apk`로 바꾸세요.

추가 실동작 검사: Python 3에서 `scripts/device_smoke.py`. 앱의 샘플 일정에 박물관을 추가했다가 제거하고, QA 기기의 권한을 철회합니다. 개인 여행 데이터를 담은 환경에서 실행하지 마세요. Pleos 초기 설치 사용자 번호가 다를 수 있어 테스트 명령은 현재 사용자를 조회합니다. 기본 test runner의 전체 APK 검색을 피하도록 테스트 클래스 목록을 지정합니다.

검증 결과와 한계는 [QA 기록](docs/qa-report.md), [설계·범위](docs/implementation-plan.md), [시연 대본](docs/demo-script.md)을 참고하세요.

추가 지시 이후 제품 코드 변경은 [모듈 책임과 모델 분담](docs/module-design.md)에 따라 **DeepSeek v4.1 Flash가 유닛별 구현**, GPT가 설계·테스트·최종 검토를 수행합니다. 그 이전에 작성한 초기 코드는 GPT 구현입니다. 소스 ZIP은 명시된 파일만 포함하고, 서명 키·SDK 캐시·빌드 캐시·모델 실행 로그·현장 검증 evidence는 포함하지 않습니다. 검증 기록은 현재 작업 폴더에 별도로 보관됩니다.

## 공모전 제출 준비

[공식 제출 안내](https://appdevchallenge.auto-hmg.io/guide/submission) 기준으로 소스·release APK·실행 방법을 준비했습니다. **접수양식(기획서), 참가자 서명·동의, 저장소/최종 커밋, 실제 이메일 제출은 별도입니다.** 이 저장소가 공모전 접수를 완료했다는 의미가 아닙니다. ‘완전 오프라인 3분’은 이번 프로젝트의 시연 목표이며 공모전 공식 규정으로 단정하지 않습니다.

SDK 이용 승인·차량 지원 범위·마켓 입점 심사는 별도입니다. 서버 TTS, LLM, 외부 관광 API, 온라인 다자 동기화, 전국 여행 콘텐츠, 장기 여행 기록은 이번 MVP에 포함하지 않았습니다.

샘플 좌표는 유적 위치의 근삿값이며 차량 진입·주차 지점으로 검증한 좌표가 아닙니다. 실제 경로 탐색 완료와 도착 자동 안내는 추가 확인이 필요합니다.
